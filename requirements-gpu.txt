# Full GRPO training stack — runs ONLY on Linux + NVIDIA GPU (CUDA).
# Do NOT install on macOS. Use on a cloud GPU box (Colab / RunPod / Lambda / Vast.ai).
#
# Versions pinned to a known-good set (mid-2026 Colab: torch 2.11 + CUDA, driver 13.0).
#
# WHY THESE ARE PINNED:
#   Leaving torch/vllm unpinned makes pip grab "latest", which drifts over time and
#   pulls a vllm built for a different CUDA than the box provides — the import then
#   dies with "libcudart.so.XX: cannot open shared object file". vllm 0.22.0 requires
#   exactly torch==2.11.0 and is built against CUDA 13, which Colab's driver supports.
#
# CUDA 13 SHARED-LIBRARY FIX (Colab):
#   vllm 0.22.0's compiled extensions need CUDA 13 .so files that are installed (by the
#   pip CUDA wheels, under nvidia/cu13/lib) but NOT on the system linker path:
#     - libcudart.so.13  -> needed by the vllm core import
#     - libnvrtc.so.13   -> needed by vllm.cumem_allocator, i.e. SLEEP MODE
#                           (enable_sleep_mode=True). If this one is missing, the
#                           cumem import fails silently and vllm reports the misleading
#                           "cumem allocator is not supported on current platform".
#
#   FIX: register the cu13/lib dir with the SYSTEM loader via ldconfig (it writes an
#   on-disk cache), so EVERY process started afterward finds the libs -- including the
#   subprocesses vLLM forks for model inspection and its EngineCore workers. The
#   notebook does this in the setup cell, AFTER pip install and BEFORE importing vllm:
#
#     with open("/etc/ld.so.conf.d/nvidia-cu13.conf", "w") as f:
#         f.write("/usr/local/lib/python3.12/dist-packages/nvidia/cu13/lib\n")
#     import subprocess; subprocess.run(["ldconfig"], check=True)
#
#   WHY ldconfig and NOT an in-process ctypes preload or LD_LIBRARY_PATH:
#     A ctypes.CDLL(..., RTLD_GLOBAL) preload only fixes the CURRENT process. vLLM
#     spawns fresh subprocesses (e.g. `python -m vllm.model_executor.models.registry`
#     for model inspection, plus EngineCore workers) that do NOT inherit in-memory
#     preloads -- they re-run `import vllm._C` and fail with
#     "ImportError: libcudart.so.13: cannot open shared object file". LD_LIBRARY_PATH
#     has the same fork-survival problem in vLLM's multiprocess architecture. ldconfig
#     updates the on-disk loader cache, which child processes DO see.
#
#   Verify:  setup cell prints "CUDA 13 libs registered with ldconfig OK", the import
#            cell prints "vllm imported OK", and LLM(..., enable_sleep_mode=True)
#            constructs without the cumem / libcudart subprocess errors.
